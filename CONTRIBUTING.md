# Contributing to KubeBrowse

We welcome bug reports, documentation improvements, tests, and code contributions.

Read the [contribution guide](docs/CONTRIBUTING.md) for development setup, coding standards, testing, and the pull request process. The [Tilt development guide](docs/TiltDevelopment.md) provides additional deployment instructions.

Please follow our [Code of Conduct](CODE_OF_CONDUCT.md) in all project interactions.

## Finding work and asking questions

Use [GitHub Issues](https://github.com/browsersec/KubeBrowse/issues) for questions, bug reports, and proposed changes. Check existing issues before opening a new one. For substantial changes, discuss the approach in an issue before implementing it.

## Submitting changes

1. Fork the repository and create a branch for your change.
2. Follow the development and testing instructions in the contribution guide.
3. Include relevant documentation and tests, and explain any checks you could not run.
4. Open a pull request against the branch agreed with the maintainer. Explain the problem, the change, and how you verified it.
